What this page is for

This HTML file is static. It loads no analytics, ads, fonts from a third party, or other third-party scripts. It does not set cookies.

Short version

Solo play keeps progress on your device. There is no account, no in-app purchase library, and no ads or analytics SDK in the shipped GitHub Pages game or the Android Capacitor wrap. Optional Wingman matchmaking uses a public relay and public STUN servers only after you host or join a room.

Data stored on your device

The game writes a few keys to browser / WebView localStorage. They stay on that device unless you clear site data or uninstall the app:

  • saucer-raid-best — best raid score (a number).
  • saucer-raid-progress — campaign JSON: sector level, salvage, run score, and upgrade ranks.
  • saucer-raid-craft — which hull you last picked (for example disc).

Nothing in the game code uploads those values to menearz or to grokbotops@gmail.com. Salvage and hull upgrades are in-game only. They are not real-money purchases.

Sound is generated on-device (Web Audio). Haptics use navigator.vibrate and gamepad rumble where the browser allows it. The Android wrap requests the VIBRATE permission for that.

Android allowBackup is true on the wrap, so the operating system may include WebView storage in a device backup. That is OS backup behavior, not a game server.

Accounts, ads, purchases, analytics

In the GitHub Pages SPA and the Android wrap, the code shows:

  • No player accounts. Auth is stubbed off (VITE_AUTH_ENABLED false; Pages/wrap auth stub). The hangar does not show Sign in on that build.
  • No in-app billing library, Play Billing, Stripe, or other IAP SDK.
  • No AdMob, AdSense, or other ads SDK.
  • No Firebase Analytics, Crashlytics, Google Analytics / gtag, Mixpanel, Sentry, Amplitude, or similar product-analytics SDK.
  • No google-services.json in the tree; the Google services Gradle plugin is not applied unless that file is present.
  • No AD_ID / advertising-ID permission in the Android manifest.
  • No camera, microphone, location, or contacts permission in the Android manifest. WebRTC is data-channel only (no getUserMedia in game source).

The repository still contains leftover better-auth / login / PGLite files used by other local preview builds. Those are not enabled in the public Pages or Android wrap described here.

Network use

Loading the web game from GitHub Pages means your browser requests HTML, CSS, JavaScript, and art from GitHub’s Pages host. The Android wrap ships those assets inside the app. The wrap still declares INTERNET because optional Wingman uses the network.

Whether GitHub, Google Play, your device vendor, or your carrier keep access logs (IP address, user agent, and similar) is unknown / to-be-verified from this repository. Those parties have their own policies. This project’s code does not implement a first-party analytics collector.

Source stylesheet src/styles.css includes a Google Fonts @import for IBM Plex Sans and Teko. The current Pages CSS under docs/assets/ does not contain fonts.googleapis.com. Whether a future rebuild fetches those fonts is to-be-verified. This privacy page does not load Google Fonts.

Optional Wingman (peer-to-peer)

Wingman runs only after you tap Host or Join and enter or generate a room code. Until then the game does not open the relay or WebRTC.

When you do host or join, the code:

  • Makes a random peer id (crypto.randomUUID when available).
  • Uses the display name Host or Join — not your Google or Play account name.
  • May use BroadcastChannel so two tabs on the same origin can find each other locally.
  • Posts signaling JSON (hello / bye / WebRTC offer, answer, and ICE candidates) to the public ntfy.sh topic sr84-{room-code} and opens wss://ntfy.sh/{topic}/ws. That relay has no app-level login.
  • Gathers ICE using public STUN: stun:stun.l.google.com:19302 and stun:stun.cloudflare.com:3478 (unless VITE_STUN_URLS is set at build time).
  • Then opens a browser-to-browser WebRTC connection. ICE candidate payloads can include network addresses. That is how WebRTC connectivity checks work.

You can instead copy a handshake tape (clipboard) and paste it in the other browser so linking does not need the relay.

After a link is up, the P2P helper sends ping/pong on a data channel to measure round-trip time. The hangar UI does not currently call the helpers that would send raid/gameplay state. Whether a later version will send game state over that channel is to-be-verified if the code changes.

ntfy.sh, Google STUN, and Cloudflare STUN are third parties. What they log is unknown / to-be-verified from this repo. Anyone who knows a room code could subscribe to that public ntfy topic while you are signaling.

There is also an unused HTTP signaling helper aimed at /api/rtc. GitHub Pages is a static site, so that route is not a live first-party API on the public game.

Sale of data

The code does not sell, rent, or broker player data. There is no ads or analytics SDK in the shipped Pages/Android game through which data could be sold. If that changes, this page should be updated to match the code.

Children

Store age ratings and whether a listing is directed at children are unknown / to-be-verified (they are listing choices, not something this repo encodes). The shipped game does not create accounts or ask for a name, email, or age. Do not let a child use Wingman with people you do not trust: signaling is on a public topic keyed by the room code.

Your choices

  • Web: clear this site’s data in the browser to drop local progress.
  • Android: clear app storage or uninstall to drop local progress.
  • Do not Host or Join if you do not want Wingman networking.

The operator does not hold a server copy of your salvage, score, or hull pick, so there is nothing extra to delete on a first-party game server. Questions: grokbotops@gmail.com.
